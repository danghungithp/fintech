The root is a thin orchestrator around the `fintech/` package: `app.py` (entry point, not in scope here) starts the Flask server that mounts routes from `fintech/routes.py`, which delegates to sibling modules (`vietcap.py`, `db.py`, `indicators.py`, `analysis.py`, `kelly.py`, `market.py`, `portfolio.py`, `screener.py`). All persistent state lives in `data/fintech.db` (SQLite), populated by the Vietcap client against public endpoints documented in README. Two standalone scripts under `tools/` are the only cross-cutting utilities: `api_probe.py` validates the upstream Vietcap API response shapes independently of the app, while `smoke_test.py` drives an end-to-end run against a live server via HTTP, exercising every top-level route (`/`, `/phan-tich`, `/sang-loc`, `/danh-muc`, `/canh-bao`, `/cai-dat`) plus all REST endpoints (`/api/health`, `/api/analyze`, `/api/kelly/calc`, `/api/screener/run`, `/api/portfolio/*`, `/api/alerts`, `/api/settings`). The project has no build step or test framework — deployment is `pip install -r requirements.txt` then `python app.py` (or `run.bat` on Windows, which auto-installs Flask and opens the browser).
